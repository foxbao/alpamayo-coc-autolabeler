# 本地候选筛选实现评审回复

感谢对本地候选筛选流程的检查。我们按评审意见修正了类别限额与去重的交互、输入输出目录、清单配置校验和重跑产物清理。下面逐项说明处理结果，并区分已修改和暂缓的建议。

## 已修改

### 类别限额和最小间距导致候选不足

已增加统一的 `balance_and_select_candidates()` 选择流程。它先按动作类别和区间时长执行限额，再在单条记录内应用最小间距；如果限额内较长的动作候选彼此过近而被抑制，会从该类别超额候选中按时长回填仍满足间距要求的候选。类别限额跨本次运行中的记录统计，间距只在每条记录内生效。回填候选会在写联系表时重新匹配图片。

这保留了“每类优先选择较长动作”的原则，同时避免长候选聚集时把远处可用候选提前过滤掉。若没有符合间距要求的候选，最终数量仍可能低于目标上限。

### 候选间距与实际窗口覆盖

本次保留严格的候选起点最小间距规则。根据数据使用者的选择，起点不足 2 秒的候选仍会被抑制；本轮没有把去重条件改成窗口覆盖判断。因此长动作的后半段仍可能没有独立候选窗口，附近的定时覆盖候选也可能被抑制。使用说明已明确写出这一限制，避免把“候选起点不重复”误解为“动作全程均被窗口覆盖”。

### Manifest 窗口参数未校验

`local_record_labeling` 现在会比较 v2 候选清单里的历史时长、未来时长和采样间隔与当前 CoC 配置。配置不一致或 v2 清单缺少窗口信息时会报错。没有窗口字段的旧版清单仍可读取，以兼容旧结果。

### 重跑后遗留旧联系表

候选清单成功写出后，程序会清理 `contact_sheets/` 下不属于本次 selected 候选的 `candidate_*.jpg`。目录中的其他文件会保留。

### 动作 JSON 输入目录与候选输出目录耦合

`local_keyframe_auto_select` 新增 `--meta-action-root`，用它指定 `full_record_meta_action.json` 所在目录；`--output-dir` 只指定候选清单和联系表输出位置。省略 `--meta-action-root` 时默认沿用 `--output-dir`，兼容此前的目录布局。

### 未使用且语义不同的第二套 `process_clip`

已从 `local_keyframe_auto_select.py` 删除未被调用、且采用单记录平衡语义的 `process_clip()`，避免它与 CLI 的跨记录类别限额行为不一致。`local_data_labeling.py` 中由其 CLI 实际调用的 `process_clip()` 仍保留，负责生成单条记录的 meta-action。

### 记录参数、个人路径和跨模块辅助函数

- `local_data_labeling`、`local_keyframe_auto_select`、`local_record_labeling` 和单事件入口都要求显式提供 `--input-root`，不再内置个人数据路径。
- 这些入口拒绝重复的 `--record`，避免重复计入类别限额或重复写出结果。
- 相机模块的 `sample_offsets()` 和 `load_rgb_frames()` 已改为公开函数名，供其他模块调用。

### 候选 ID 和筛选门槛说明

使用说明指出候选 ID 会随筛选参数变化，选择候选时应以当前 `segment_candidates.json` 为准。文档明确说明候选阶段默认的 1 秒动作时长是额外的筛选门槛，与本地动作分类器生成区间时的最短长度规则不同；也说明了最小间距和窗口覆盖之间的限制。

## 暂缓的建议及原因

- **按窗口覆盖能力抑制候选**：本轮依照使用者选择继续严格应用起点间距。窗口覆盖感知会改变候选抑制规则；目前保留至少 2 秒的起点间距，并把长动作可能无法被一个窗口完整覆盖作为已知限制记录。
- **降低候选模块导入 `torch` 的启动开销**：这是本地导入结构造成的启动耗时，不是候选逻辑必须依赖 PyTorch，也不影响筛选结果。消除它需要拆开候选读取使用的动作类别/JSON 类型与动作分类模块的导入关系。该命令目前主要用于调试和候选生成，几秒启动时间尚未成为实际阻碍，因此先不增加模块拆分；若后续频繁启动或批量作业受影响，再单独处理。PAI 的 `src/meta_action/` 源码不会因此需要修改。
- **原子写入 manifest**：这能降低程序恰好在写 JSON 时中断而留下不完整文件的风险，但不改变正常完成时的结果，与本轮修复的候选选择行为无关。当前先保持写入方式简单；若批量运行中断恢复成为常见需求，再增加临时文件加原子替换。
- **指定动作类别却没有候选时的提示**：这是操作提示的改进，不影响筛选正确性；目前可从 manifest 中看到实际候选和过滤状态，暂不增加另一套提示逻辑。
- **稀有动作优先级**：这会改变跨记录样本的抽取政策。当前按动作区间时长和既定类别限额处理；在没有明确的稀有度权重或期望分布前，不引入新的排序规则。
- **允许 `--minimum-separation-sec 0`**：零值会关闭候选间距限制，而当前已决定保持严格的间距规则，因此不开放这个选项。

## 新一轮评审后的补充修正

- **回填数量的保证范围**：算法保持“较长动作优先”，不回溯替换已选候选。因此 `--target-count` 是每类上限，并非必须填满的配额；即使存在另一组较短候选可以填满上限，当前单趟回填也可能选择数量更少。使用说明已改成准确描述这一行为，本轮没有改变抽样策略。
- **CLI 类别摘要**：输出现在写明 `available`、最终 `selected` 数、类别 `cap`，并注明已应用间距规则，避免把间距抑制造成的数量变化误读为类别限额。
- **候选状态前置条件**：`balance_and_select_candidates()` 现在会拒绝尚未经过初始窗口检查和间距筛选的 `pending` 动作候选，防止它们绕过类别上限。
- **v2 manifest 识别**：除数值或字符串形式的 schema version 2 外，也根据 `action_candidates` / `coverage_candidates` 结构识别 v2 清单；缺少 `window` 会报错。没有窗口字段的旧版扁平清单仍能读取。
- **补充测试及维护文字**：新增跨记录回填上限、回填动作与 coverage 优先级、贪心回填可能未填满、pending 状态拒绝、v2 缺 window、旧版无 window 兼容，以及分离 `--meta-action-root` 与输出目录的 CLI 集成测试。同步更新了 `--record` 参数帮助和候选生成函数文档。

本轮完整测试为 `75 passed, 1 warning`；相关文件 Ruff 检查和 `git diff --check` 均通过。警告仍是环境中的 `pynvml` 弃用提示。
